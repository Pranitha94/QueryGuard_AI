## Plan and gates
First inspect this repo/environment, write IMPLEMENTATION_PLAN.md with phases/acceptance criteria. Implement and RUN tests phase by phase. Use strict vertical TDD: write one behavior test, run and observe expected failing assertion, implement minimal behavior, verify green; repeat. 1. Admin/setup credentials separate from runtime. Runtime must refuse superuser/write-capable connections. Do not equate default_transaction_read_only alone with least privilege.
2. SQLGlot fail-closed AST validator: exactly one allowed read-only SELECT/CTE/set query; explicit function/table/column/type/node allowlists; reject DML/DDL at all depths, SELECT INTO, locks, recursive CTEs, catalog/system/foreign schema reads, unauthorized functions/table functions, qualification tricks, casts to user-defined types, huge/complex expressions. Resolve table/column lineage through nested queries/CTEs/aliases; stars must expand ONLY to allowed columns or be disallowed. Bound SQL/question size, query depth/complexity, enforce row cap even if model LIMIT exceeds it. SQLGlot qualification alone is NOT a permission policy. Recheck qualified AST. AST-reviewed executable SQL only. Use read-only transactions, SET LOCAL timeout/search_path, bound result fetch, safe exception handling. Audit accepted/rejected/provider-error/execution-error requests without raw questions, result values, secrets, DSNs or raw database errors; bounded session history and session isolation.
3. Pydantic structured output provider interface: deterministic demo provider clearly labeled SIMULATED/TEMPLATE, NOT real LLM; no benchmark answer-key imports/lookups or fake scores. Support questions through honest documented templates, joins/aggregation/CTE/date/nested. Ollama /api/chat JSON schema structured output via HTTP with timeout and strict parsing. Optional Gemini adapter env only (can omit if quality suffers). Baseline vs schema-aware prompt builder and relevant-table/column retrieval from live database introspection plus relationship closure. Untrusted schema metadata/data are not instructions. No row samples sent to providers. Ambiguity -> clarification; unknowns -> refusal. Model failure no silent demo fallback. Simple factual summaries computed ONLY from result values, never LLM conjecture.
4. FastAPI REST documented endpoints health/schema/query/history/evaluation; safe validation/errors, local-only default, no misleading production authentication guarantees. Streamlit + Plotly polished cohesive workspace with chat/history, schema explorer, SQL viewer, validation, tabular results, interactive appropriate charts, CSV, latency/status and evaluation dashboard.
